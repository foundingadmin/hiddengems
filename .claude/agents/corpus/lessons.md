# Lessons

What agents learned doing the work, kept until a directive adopts it. Builders and `corpus-steward` add lessons;
read-only agents report them for `corpus-steward` to add. `corpus-steward` reviews them and proposes adoption as an
amendment (`corpus/amendments.md`). Lessons are evidence, never orders:
an agent follows its directive, not this file, until the lesson is adopted.

Format: `L<number>`, date, the agent that learned it, the lesson in one or two sentences, the evidence, the directives
that would benefit, and a status (`open`, `adopted in <agent> v<x>`, or `declined`).

## L1 · 2026-11-03 · pr-verifier
The GitHub connector rewrites the attribution footer of PR bodies to its own `_Generated by ..._` line, whatever
the session wrote, so a PR body footer is not something a branch owner can fix.
- Evidence: PRs #18 and #19 were written with the required footer and saved with the connector's line.
- Benefits: `pr-verifier` (do not block on the PR body footer; check commit trailers instead).
- Status: adopted in pr-verifier v1.1.

## L2 · 2026-11-03 · design-verifier
Sample data never produces warned or failed runs or multi-step fixes, so states that only appear on problems were
verified by injecting markup in the browser. That proves styling, not behavior.
- Evidence: PR #17, #18 and #19 verifications.
- Benefits: `data-builder`, `screen-builder` (add a sample provider switch or fixture that produces warnings and
  failures, so problem states render from real data).
- Status: open.

## L3 · 2026-11-03 · design-verifier
A layout that reads well at 1440 and 390 can still break in between; the schedule row's name lane collapsed between
960 and 1150 pixels of list width.
- Evidence: PR #18 first review.
- Benefits: `design-verifier`, `screen-builder`, `facet-builder` (always screenshot a middle width, about 1100).
- Status: adopted in design-verifier v1.1.

## L4 · 2026-11-03 · facet-builder
Several builders asking for Facet parts at once collide in the same stylesheets; batching requests into one
`ds/` branch that merges before the feature branches avoids conflicts.
- Evidence: the 12 requests from the Rating lab and Logs went into one batch after PR #18.
- Benefits: vice principal ordering (in the README), `facet-builder`.
- Status: adopted in README v1.0 ("Order of work").

## L5 · 2026-11-03 · content-verifier
When one rule changes across AGENTS.md, the README and the directives (here, where tasks branch from and who merges
where), grep every file for the old wording before committing; six findings on the corpus PR were leftovers.
- Evidence: PR #21 content review (findings 3 to 8).
- Also: when a section moves between files, grep for references to its old heading (pr-verifier, PR #21).
- Benefits: `corpus-steward` (amendments, drift check), `repo-hygiene` (corpus drift).
