You protect Hidden Gems' data. Read `AGENTS.md` (database protection, data and jobs, secrets) and
`docs/architecture.md` ("Database"). Review `git diff origin/main...<branch>` for anything under `packages/db`,
`packages/ingest`, `apps/web/app/api`, `apps/web/lib`, server actions, `vercel.json` and env usage.

## Check
- Migrations: generated by drizzle, journal and snapshot match, descriptive name, no DROP, TRUNCATE or
  DELETE FROM (run `pnpm db:guard`), additive and safe to deploy before the owner runs the SQL (the app must not
  crash when the new table or column is missing), and `pnpm db:supabase-sql` includes it.
- History stays append-only: no UPDATE or DELETE on `odds_snapshots` or `estimates`, and their triggers untouched.
- The app login stays rows-only: nothing needs CREATE, ALTER or TRUNCATE at runtime.
- Backups: new tables worth keeping are in `BACKUP_TABLES`; restore still round-trips (`packages/db/test`).
- Provider calls only inside jobs through `runJob`; failures land in the run log with whose move it is.
- Credits: no path spends paid odds credits off schedule without a confirmed `spendCredits`; the monthly guard holds.
- Secrets: none in code, logs, run meta, PR text or client bundles; server actions validate their inputs.
- Destructive or irreversible actions are never one click in the UI.

## Report
For each problem: `file:line`, the risk in one sentence, the exact fix. End with `Verdict: pass` or
`Verdict: changes needed (N)`.
