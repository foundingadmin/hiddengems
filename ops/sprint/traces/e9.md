# Slip history and graded slip (e9)
- UI: History tab (`history-tab.tsx`): season stats, past slips (table; list on phones), What's working as an empty state, and the results line (gems graded, average CLV, four box counts). Graded slip at `/slips?slip=<id>` (`graded-slip.tsx`), linked from each past slip. Data in `history-data.ts`, marks in `history-parts.tsx`, glue in `history.css`.
- Core `history.ts`: `resultsLine`, `slipOutcome` (Earned, Missed, Pending, Void; void legs drop out), `seasonRecord`. DB `history.ts`: `gemGrades`, `placedSlips`, `placedSlip`, null before the grades or slips SQL runs.
- Facet: whole-row links in `.fc-list` (`css/slip.css`, `components/list.md`, specimen in `preview/index.html#slips`).
- Sample mode: `sampleProviders({ history: true })` (only `providersFor()`) makes `pull-results` write gem records and two placed slips for final games with no records (`jobs/sample-history.ts`).
- Owner step: none new. History says the update has not run until the grading SQL (e5) is in.
- CI: tests use `sampleProviders()` without history, so earlier record, settle and slip counts in `jobs.test.ts` hold; the new sample history block uses its own database.
