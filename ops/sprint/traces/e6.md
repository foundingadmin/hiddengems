# e6 · Jeweler

- Desktop: the rail's Ask the Jeweler adds `?ask=1` and opens a Facet sheet over the page (`gem=<id>` adds the gem chip); closing drops only `ask`. Phone and direct links: `/jeweler`, `/jeweler?gem=<id>`. No slip chip yet; the seam is `JewelerContext.slip` and a comment in the chips.
- Files: `apps/web/components/jeweler.tsx` and `.css`, `apps/web/app/jeweler/{page,actions}`, `apps/web/lib/jeweler.ts`, one rail link and the sheet mount in `shell.tsx`; `packages/ingest/src/jeweler.ts`, `providers/anthropic.ts`, `http.ts` (`postJson`), `runner.ts` (`Job.providerId`, provider `fetch` for tests).
- Calls: an ask is interactive, so a server action runs it at once as the `ask-jeweler` job through `runJob` and it lands in the pull log. Guard: no call without `ANTHROPIC_API_KEY` and a cap; spend in `provider_usage` (cents, per UTC month).
- Schema: `job_settings` has no number column, and adding one breaks its full-row selects (backup, Data health) until the SQL runs, so the cap is a new table `provider_caps` (migration 0005). It is in `BACKUP_TABLES`; `dumpDatabase` skips a table that does not exist yet.
- Owner steps: run the `pnpm db:supabase-sql` output (staging, then production); add `ANTHROPIC_API_KEY`; set the cap (SQL in `docs/architecture.md`, "The Jeweler"). Confirm Sonnet 5.5 prices in `JEWELER.price` ($3 and $15 per million tokens assumed).
- CI: `packages/ingest/test/jeweler.test.ts` and `packages/db/test/safety.test.ts` use a fake fetch and PGlite; no secrets.
